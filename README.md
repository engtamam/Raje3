# راجِع · Raje3

**يرجّع زبونك عبر الواتساب** — منصة تذكير واحتفاظ آلي (Smart Reminder & Retention SaaS) للأنشطة
الخدمية الدورية. تُرسل كل رسالة **باسم المنشأة وهويتها وشعارها**، لا باسم المنصة.

> منتج خاص. جميع الحقوق محفوظة. أبقِ هذا المستودع **خاصاً**.

---

## المبدأ المعماري (كيف نبني)

راجِع يقف على منصة **base-services**: عشرات الخدمات الخلفية العامة، جاهزة الإنتاج. نحن **نشغّلها من
صورها المنشورة ولا نملك كودها ولا نعدّله أبداً** — نكيّفها عبر الإعداد فقط: متغيرات البيئة، اختيار
الـ adapters، وقيم Helm. منطق راجِع الخاص (العميل، الأصل، الخدمة، التذكير، النقاط، القطاع) نبنيه
بأنفسنا في `services/` بنفس أسلوب base-services القوي، من قالبها `_template`.

القاعدة الحاكمة، بلا استثناء:

| الحالة | التصرف |
|---|---|
| المنصة تملك الميزة | فعّلها بالإعداد |
| فيها خلل | بلّغهم + التفاف مؤقت خلف port |
| ينقصها ميزة **عامة** | اطلبها منهم + adapter مؤقت لحين وصولها |
| ينقصها ميزة **خاصة بمجالنا** | لن تأتي أبداً — ابنِها في `services/` |

**لا fork. لا patch.** مخرجنا الوحيد عند النقص هو port بمنفذين، لا تعديل صورة.

## الهيكلة

```
config/     هوية المنتج — المكان الوحيد لاسم راجِع وبراندها (rename بملف واحد)
ci/         حرّاس يفشلون البناء قبل أن يفشل الإنتاج
services/   خدماتنا الخاصة (business logic)، من قالب _template — تُضاف مرحلياً
platform/   base-services: الـ chart + حزمة CI فقط (sparse submodule). لا يُعدَّل إطلاقاً
deploy/     خط أنابيب التنصيب على السيرفر (k3s) — provision / install / update
ui/         الواجهات (المنشأة: لوحة + إدخال ميداني · السوبر أدمن)
data/       "المحاور" — القطاعات والخدمات والقوالب، تنمو بلا deploy
docs/       التصميم، يُكتب قبل الكود
brand/      رموز الألوان والشعارات
```

## نسخة جديدة من المستودع

```bash
bash scripts/setup.sh      # يهيّئ submodule المنصة (sparse: chart + CI فقط، ~0.4M)
```

## إعادة تسمية المنتج

عدّل `config/product.json` → `identity` و `brand` فقط. **لا تلمس `identifiers`** — قيمها مكتوبة
في بيانات يملكها العملاء (توكنات، روابط إلغاء الاشتراك الموقّعة). `ci/check_product_config.py`
يفشل البناء إن حاولت.

## الخدمات الخاصة (`services/`)

| الخدمة | تملك | المرحلة |
|---|---|---|
| `operations` | العملاء، الأصول، سجلات الخدمة، الموظف + PIN، الإدخال الميداني | MVP |
| `reminders` | قواعد التذكير + التعلّم التكيفي + حساب الموعد القادم | MVP |
| `catalog` | القطاعات، الخدمات، الحقول الديناميكية، القوالب القطاعية | MVP |
| `loyalty` | كسب/استبدال النقاط + العتبات + عبر الفروع | لاحقاً |
| `campaigns` | التصنيف + الحملات + منع الحظر + بوابة إلغاء الاشتراك | لاحقاً |

## الحالة

**سقالة أولية.** هوية المنتج، حارس الإعداد، وربط منصة base-services (المثبّتة على `v0.12.2`) جاهزة.
الخدمات الخاصة وخط الدبلوي يُبنيان مرحلياً حسب خارطة الطريق.
