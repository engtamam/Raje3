# تشغيل خادم راجِع — بالسكربتات وحدها

**لا شيء في هذا الدليل يُكتب باليد.** كل فعلٍ هنا سكربتٌ في `deploy/`، وكل سكربتٍ يشرح نفسه في
رأسه. وإن وجدتَ نفسك تكتب `kubectl` يدوياً، فذلك عيبٌ يُسجَّل لا عادةٌ تُتَّبع.

**مبدآن يحكمان كل ما يلي:**

1. **الخادم يحمل ما يشغّل، لا ما نكتب.** الشيفرة داخل الصور. الخادم يأخذ السكربتات والقيم
   والـchart فقط.
2. **كل صورة مُثبَّتة ببصمتها (`sha256`) لا بوسمها.** الوسم يُحرَّك، والتراجعُ المُثبَّت بوسمٍ أملٌ
   لا ضمان.

---

## الجهات الثلاث، ومن يفعل ماذا

| أين | ماذا فيه |
|---|---|
| **جهازك** | المستودع، ويبني الصور، ويحزم ويشحن |
| **`ghcr.io`** | الصور السبع — ومنها وحدها يسحب الخادم |
| **الخادم** | `/opt/raje3` (السكربتات والقيم)، وk3s يشغّل العنقود |

**الخادم لا يقرأ GitHub.** الدفع إلى GitHub يحفظ العمل ولا يغيّر شيئاً في الإنتاج.

---

## أولاً: تثبيتٌ من الصفر — خادمٌ جديد

**1 — أنشئ رمز GitHub** من `github.com/settings/tokens` بصلاحية `read:packages` (وللدفع
`write:packages`). **لا يُكتب في أي ملفٍ داخل المستودع.**

**2 — من جهازك، ابنِ الصور وادفعها:**
```bash
export GHCR_TOKEN='…'
bash deploy/publish-images.sh              # السبع كلها
bash deploy/publish-images.sh operations   # واحدة، بعد إصلاح
```
يبني ويدفع، **ويكتب البصمات في ملفات القيم** — فما في المستودع هو ما في السجلّ. ثبّتها:
```bash
git add -A && git commit -m "بصمات الصور" && git push
```

**3 — احزم واشحن:**
```bash
KEY=/path/to/key.pem bash deploy/pack.sh --to root@HOST
```
يبني حزمةً صغيرة (السكربتات · القيم · البذور · الـchart · إقلاع المنصة)، ويرفعها إلى
`/opt/raje3`، ويحتفظ بالسابقة في `/opt/raje3.prev`. وتحمل الحزمة **ختم الإصدار** — commit
ونسخة المنصة ووقت البناء — لأن شجرةً منسوخةً باليد تأخّرت إصداراً كاملاً كلّفتنا يوماً من
تشخيصٍ خاطئ.

**4 — على الخادم، أمرٌ واحد:**
```bash
ssh root@HOST 'cd /opt/raje3 && GHCR_USER=… GHCR_TOKEN=… bash deploy/install.sh'
```
`install.sh` **هو الأمر الواحد**: يستدعي الإقلاع، ثم preflight، ثم يسكّ الأسرار، ثم ينشر
الأربع والعشرين خدمة على بصماتها. وهو تفاعليّ افتراضاً؛ `ASSUME_YES=1` يتخطّى الأسئلة.

**5 — أثبت، لا تفترض:**
```bash
KEY=/path/to/key.pem bash deploy/verify-fleet.sh
```
يقارن `imageID` الفعليّ على العنقود بالبصمة المشحونة، **خدمةً خدمة**. لأن `git commit` يجعل
إعادة التثبيت تبدو مُنجَزة، ولا شيء بين ذلك وبين العنقود يُثبتها.

## ثانياً: شحنة تعديل — الحالة اليومية

بعد أن تصير الشيفرة خضراء (السويتات الست وكل البوابات):

```bash
export GHCR_TOKEN='…'
bash deploy/publish-images.sh                       # 1. ابنِ وادفع
git add -A && git commit -m "البصمات" && git push    # 2. ثبّت البصمات
KEY=…/key.pem bash deploy/pack.sh --to root@HOST     # 3. احزم واشحن
ssh root@HOST 'cd /opt/raje3 && bash deploy/install.sh'   # 4. انشر
KEY=…/key.pem bash deploy/verify-fleet.sh            # 5. أثبت
```

**خمس خطوات، بهذا الترتيب، ولا يُتخطّى منها شيء.** أخطرُ ما يمكن فعله هو بناء صورةٍ من شجرةٍ
فيها عملٌ غير مُثبَّت: تصير الصورة تحمل شيفرةً لا يعرفها أحد.

## ثالثاً: تجديد رمز السجلّ

الرمز في العنقود سرٌّ اسمه `ghcr` في `base-services`. لتجديده — بعد إلغاء القديم:

```bash
ssh root@HOST "kubectl -n base-services create secret docker-registry ghcr \
  --docker-server=ghcr.io --docker-username=USER --docker-password='TOKEN' \
  --dry-run=client -o yaml | kubectl apply -f -"
```
`apply` يستبدل ولا يشتكي — وهو نفس السطر في `bring-up.sh`.

**والإثبات سحبٌ حقيقيّ، لا وجود السرّ:**
```bash
ssh root@HOST 'kubectl -n base-services rollout restart deploy/operations'
ssh root@HOST 'kubectl -n base-services get pods -w'
```
`Running` = نجح. `ImagePullBackOff` = الرمز خطأ أو صلاحيته ناقصة.

> **ملاحظة:** الحاويات العاملة لا تعيد السحب. إلغاء رمزٍ لا يُسقط ما يعمل — يظهر أثره عند أول
> إعادة تشغيل أو نشرة.

## رابعاً: ما تشغّله قبل كل شحنة، على جهازك

```bash
for s in operations reminders loyalty insights portal campaigns; do
  (cd services/$s && python -m pytest tests -q)      # سويت واحدة في كل مرة
done
for g in ci/check_*.py; do python "$g" || echo "RED $g"; done
(cd apps/console && npx tsc --noEmit && npx vitest run)
```

**سويةً واحدة في كل مرة.** التوازي يُجوّع المعالج فتبدو السويتات معلّقة وليست كذلك.

ومن البوابات واحدةٌ تخصّ الشحن مباشرةً:
`ci/check_every_values_file_renders_against_the_chart.py` — تُصيّر كل ملف قيم على الـchart.
ملفٌّ لا يُصيَّر يوقف المثبِّت عند الخدمة التي عنده، **فتُحدَّث ما قبلها ويبقى ما بعدها على صوره
القديمة** — عنقودٌ نصفُ منشور. حدث هذا فعلاً بمفتاحٍ كُتب في جذر ملف القيم بدل `env:`.

## خامساً: النظر إلى عنقودٍ يعمل

| السؤال | السكربت |
|---|---|
| هل يشغّل ما ثبّتناه؟ | `deploy/verify-fleet.sh` |
| هل المسارات تعمل فعلاً، لا «موجودة»؟ | `deploy/probe-live.sh` |
| هل الوضع الأمنيّ سليم؟ | `deploy/check-posture.sh` (و`--quiet` للأخطاء وحدها) |

**و«موجود» غير «يعمل».** `check_deploy_wiring.py` يقرأ ملفات؛ `probe-live.sh` ينادي العنقود
الحيّ — والعطب الذي يمسكه يترك كل ملفٍ صحيحاً وكل probe أخضر.

## سادساً: إثباتات المنتج — أنه يفعل ما نبيعه

سكربتات `prove-*.sh` تنادي **الصورة العاملة على بصمتها المثبَّتة** بنداءات حقيقية:

| السكربت | ما يُثبته |
|---|---|
| `prove-points.sh` · `prove-loyalty.sh` · `prove-redeem-merge.sh` | النقاط والاستبدال |
| `prove-limits.sh` · `prove-quota.sh` | الحدود والحصص |
| `prove-identity.sh` · `prove-branch-scope.sh` | الهوية وعزل الفروع |
| `prove-onboarding.sh` · `prove-trial.sh` · `prove-plans.sh` | التسجيل والباقات |
| `prove-insights.sh` · `prove-confirmation.sh` · `prove-ladder.sh` | المؤشرات والرسائل والسلّم |
| `prove-retention.sh` · `prove-unsubscribed.sh` | الاحتفاظ والمنشأة المنقطعة |
| `prove-seams.sh` · `prove-bespoke.sh` | اللحامات والقوالب الخاصة |

تُشغَّل بعد كل شحنة كبيرة، لا مع كل تعديل.

## سابعاً: المنصة (`platform/`) — للقراءة فقط

```bash
GHCR_TOKEN=… bash deploy/repin-platform.sh v0.16.15          # يعيد التثبيت
GHCR_TOKEN=… bash deploy/repin-platform.sh v0.16.15 --check  # يبلّغ بالانحراف ولا يغيّر
```
يضع صور المنصة كلها على **إصدارٍ واحد** محلولٍ إلى بصمات. وبوابة
`check_the_platform_we_pin_is_the_platform_we_vendored` تُطابق ما نُثبته بما وضعناه فعلاً —
لأن `platform/` بقي على v0.16.14 بينما سبعة عشر ملفاً تُثبّت v0.16.4، وكل شيءٍ فوقه بقي أخضر
عشرة إصدارات.

## ثامناً: حين يفشل شيء

**1 — المثبِّت وقف في منتصفه.** أصلح السبب المطبوع، ثم أعد `pack.sh` و`install.sh`. المثبِّت
قابلٌ لإعادة التشغيل، والخدمات التي نجحت تُتخطّى بلا ضرر.

**2 — `ImagePullBackOff`.** رمز السجلّ. القسم الثالث أعلاه.

**3 — الخدمة تعمل بصورةٍ قديمة.** `verify-fleet.sh` يسمّيها. غالباً بصمةٌ لم تُثبَّت أو حزمةٌ
لم تُشحَن.

**4 — العودة إلى ما قبل الشحنة.** الحزمة السابقة في `/opt/raje3.prev` كما هي.

---

## تاسعاً: ما لا يفعله أي سكربت — وهو بيدك وحدك

- **رموز GitHub**: إنشاؤها وإلغاؤها. وبعد كل استعمال على جهازك: `docker logout ghcr.io`
  (الرمز يُحفظ في `~/.docker/config.json`).
- **مفتاح النسخ الاحتياطي ووجهته**: مفتاحٌ خارج الخادم ووجهةٌ خارجه — وإلا فالنسخة على القرص
  الذي تحميه منه.
- **بيانات ميتا**: `config_id` وتشغيل الإرسال الحقيقي.
- **أي رسالة حقيقية لشخصٍ حقيقي**: قرارٌ لا يُؤتمَت.
