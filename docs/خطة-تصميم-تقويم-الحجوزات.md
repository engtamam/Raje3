# خطة: تقويم حجوزات باحترافية أعلى — عرض سنة/شهر/أسبوع/يوم

## السياق

شاشة «الحجوزات» الحالية (`apps/console/src/screens/Bookings.tsx`، ١٨٧٣ سطر) فيها عرضان بس:
**يوم** و**أسبوع** — شبكة أعمدة موظفين × صفوف وقت، بسحب وإفلات، هوية بصرية خاصة بالشاشة (مرحلة ٦-٧
من `docs/خطة-تنفيذ-الحجوزات.md`، كلها مُنجَزة ومُختبَرة).

منافس (لقطات الشاشة المرفقة) عنده **أربعة مستويات عرض**: سنة (١٢ شهراً مصغّرة بنقاط كثافة)، شهر
(تقويم شهري بعدد الحجوزات باليوم)، أسبوع (أعمدة أيام)، يوم (أجندة بطاقات مواعيد فعلية بالاسم
والوقت ورقم الجوال). قرار تمام: **نبنيها كاملة، عالية الاحترافية، مو بس شهر**.

## القرار المعماري: عرضان جديدان (شهر، سنة) فوق نفس البيانات، مو نظام موازٍ

لا نبني تقويماً منفصلاً يقرأ بياناته بطريقة ثانية — نفس `Booking`، نفس `slots_between`، نفس
منطق التصفية بالفرع/مقدّم الخدمة الموجود. الفرق الوحيد: **شهر/سنة يحتاجان عدد الحجوزات باليوم**،
لا كل حجز بتفاصيله (سحب ٣٦٥ يوماً من الحجوزات الكاملة لعرض السنة تبذير حقيقي — نفس الدرس اللي
تعلّمناه بملفات الإحالة/العمولات هالجلسة نفسها: لا تجلب أكثر من اللي تحتاجه الشاشة).

## ١. الخلفية — مسار عدّ خفيف، لا حجوزات كاملة

**ملف**: `services/bookings/app/api/v1/bookings.py` — مسار جديد بجانب `GET /bookings` الحالي
(اللي يبقى كما هو، يخدم يوم/أسبوع فقط).

```
GET /api/v1/bookings/counts?branch_id=&start=YYYY-MM-DD&end=YYYY-MM-DD
→ {"counts": {"2026-01-04": 3, "2026-01-05": 0, ...}}
```

**التنفيذ**: دالة جديدة بـ`app/core/stores.py` — تستعلم `BOOKING_SLOTS` مباشرة (نفس فهرس
`slots_between` الموجود) لكن **بلا استدعاء `self.get()` لكل صف** (اللي يجلب الحجز الكامل) —
فقط تعدّ الصفوف مجمّعة بـ`bucket`. هذا يخليها رخيصة حتى لعرض سنة كاملة (٣٦٥ يوماً)، بعكس
`slots_between` الحالية اللي مبنية أصلاً ليوم/أسبوع بس (حد `limit=500` وتفعيل `self.get()` لكل
صف — مناسب ليوم واحد، غير مناسب لسنة).

**لا حد أقصى صارم** — عدّ الصفوف المطابقة بالفهرس، لا الحجوزات نفسها، فحتى محل مزدحم (آلاف
الحجوزات بالسنة) يبقى استعلام العدّ رخيصاً.

**اختبار**: ملف اختبار جديد يثبت العدّ صحيح عبر مدى متعدد الأشهر، وأنه لا يُرجع تفاصيل الحجز
(لا اسم، لا هاتف) — هذا المسار للعدّ فقط، التفاصيل تُجلب عند فتح يوم بعينه بالمسار الحالي.

## ٢. الواجهة — نوع العرض يتوسّع لأربعة، لا اثنين

**ملف**: `apps/console/src/screens/Bookings.tsx`

```ts
const [view, setView] = useState<'day' | 'week' | 'month' | 'year'>('day');
```

**مكوّنان جديدان** (بنفس لغة التصميم المعتمدة هالجلسة: شريط تمييز متدرّج للعنصر النشط،
`rounded-2xl`، رفعة حقيقية عند المرور `hover:-translate-y-0.5`، شرائح أيقونات بحلقة وتدرّج):

- **`BookingsMonthView.tsx`** — شبكة ٧×٥/٦ (أيام الأسبوع × أسابيع الشهر)، كل خلية يوم تعرض
  رقم اليوم + عدد الحجوزات (نقاط كثافة أو رقم صغير، مو تفاصيل) — **يجلب من `/bookings/counts`
  فقط**. ضغطة على يوم → `setView('day'); setDate(thatDay)`.
- **`BookingsYearView.tsx`** — ١٢ شهراً مصغّراً بنفس فكرة `BookingsMonthView` لكن كل شهر
  مصغّر (زي لقطة المنافس الأولى: ١٢ تقويماً صغيراً بنقاط). ضغطة على شهر → `setView('month')`
  على ذاك الشهر؛ ضغطة على يوم داخل الشهر المصغّر → مباشرة لعرض اليوم.

**التنقّل الموجود** (أسهم يمين/يسار، «اليوم») يتمدّد ليتحرّك بوحدة العرض الحالي: يوم بيوم،
أسبوع بأسبوع، شهر بشهر، سنة بسنة — نفس الدالة `addDays`/ما يعادلها بمنطق شهر/سنة حقيقي
(`date-fns`-style، لا حساب يدوي عرضة لخطأ نهاية الشهر).

**مفتاح العرض بالأعلى** (السطر اللي فيه أزرار «يوم/أسبوع» اليوم) يتوسّع لأربعة أزرار.

## ٣. الترتيب

| # | المرحلة | الوصف |
|---|---|---|
| 1 | مسار العدّ الخلفي + اختباراته | `GET /bookings/counts`، عدّ صرف بلا تفاصيل |
| 2 | `BookingsMonthView.tsx` + اختباراته | شبكة شهر، ضغطة يوم → عرض يوم |
| 3 | `BookingsYearView.tsx` + اختباراته | ١٢ شهراً مصغّراً، ضغطة شهر/يوم → عرض شهر/يوم |
| 4 | دمج الأربعة بمفتاح عرض واحد + التنقّل الموحّد | لا كسر ليوم/أسبوع الحالي أثناء الدمج |
| 5 | تحقّق شامل: تحقّق أنواع، الاختبارات كاملة، فحص بصري | مطابقة مستوى الاحترافية المطلوب |

## ما لا يتغيّر

يوم/أسبوع (السحب والإفلات، الهوية البصرية، منطق التعارض) — **بلا لمس**. هذا بناء إضافي فوق
أساس مُختبَر (٣٦٦ اختباراً بخدمة الحجوزات وحدها)، لا إعادة كتابة.
